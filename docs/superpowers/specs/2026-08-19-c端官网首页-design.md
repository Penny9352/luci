## 1. 目标与范围

### 1.1 这一页要做成的事

按优先级：

1. **说清「凭什么是你」** —— 访客多半已经在用豆包/Kimi/元宝，它们全部免费。「免费开始使用」在这个市场没有说服力，页面必须先回答差异，再谈注册。
2. **拉注册** —— 主 CTA 全站统一，贯穿七个区块。
3. **展示产品全貌** —— 让人看到界面，降低"这到底是什么"的不确定感。

### 1.2 明确不在本次范围内

- 应用点落地页模板（P1，承接小红书/抖音投放，另起一轮）
- 定价页、开发者页、生态应用详情页（P2，本次仅导航留位或锚点）
- B 端企业站（第二阶段，独立项目）
- 英文/海外版

### 1.3 成功标准

- 首屏在 1440×900 视口内，定位、副标题、双 CTA、模拟对话窗口顶部全部可见，无需滚动
- 页面所有对外表述均可回溯到 `01-现状分析` §2 的产品事实，且不触碰 §5.1 禁区
- 移动端（375px）七个区块全部可用，模拟对话与粒子动画有降级方案
- 首屏 LCP < 2.5s（4G），`prefers-reduced-motion` 下所有动画停止且内容完整

## 3. 视觉系统

### 3.0 关于第三色的更正

spec v1.0 把第三色定为电蓝 `#0052ff`，依据是 `lucimix.com/favicon.svg`。**这个依据是错的** —— 那是 B 端/通用标记。用户提供的 `assets/brand/C端LOGO.svg` 显示 C 端标记是**橙色渐变** `#FF8559 → #EF682D`，且产品 CSS 中主橙 `#ff6b00` 出现 14 次，界面上光点「+」、邀请卡片、文件库选中 tab、交叉验证进度条的「开始输出」全部用它。

改为 `#ff6b00` 之后有三个额外好处：

1. 与金 `#d4b87a` 同属暖色系 —— 金是橙降饱和提亮度的同族色，黑/金/橙是一条连续色相线；黑/金/蓝是三个不相干体系
2. 与产品、logo 完全一致，点 CTA 进入产品无视觉断层
3. 对比度大幅改善：`#ff6b00` 在黑底上 7.4:1，电蓝仅 3.7:1

### 3.1 色板

参考 Claude 首页的**橙 / 黑 / 点缀**方案（用户指定）。从该参考里取的是三条结构性做法，不是色号：

1. **底色偏暖，不用纯黑** —— `#000` 冷、硬、廉价感
2. **橙是主角但用得极克制** —— 大量留白托着少量橙，不是满屏橙
3. **明暗交替** —— 整页不一色到底，中段有浅色区块换气（见 §3.1.1）

角色分工：**橙 = 品牌与动作**（CTA、标题重点词、区块序号、图标）；**金 = 语义点缀**（分歧/冲突标记、细线、数据）；**白 = 已确定**（共识、正文）。金的语义职责不可删除——它是 §4.2 交叉验证那一屏的表达手段。

```css
:root {
  /* 底 —— 暖近黑，与产品暗色主题 (#0f0f0f~#1a1a1a) 及 logo 暗底同源 */
  --bg:            #1a1917;
  --bg-elev:       #232220;
  --surface:       #2b2a27;   /* 卡片、窗口 */
  --surface-2:     #34322e;   /* 卡片内嵌层 */

  /* 浅色区块 —— 中段换气 */
  --bg-light:        #f2efe9; /* 暖米，非纯白 */
  --text-on-light:   #1a1917; /* 15.3:1 */
  --text-on-light-2: #57544d; /*  6.6:1 */
  --orange-on-light: #b34700; /*  4.8:1 —— 浅底专用深橙，见下 */

  /* 描边 */
  --border:        #ffffff14;
  --border-strong: #ffffff29;
  --border-gold:   #d4b87a3d;
  --border-light:  #1a191714;

  /* 文字（暗场） */
  --text:          #f7f5f2;   /* 16.1:1 */
  --text-2:        #a3a09a;   /*  6.7:1 */
  --text-3:        #8a877f;   /*  4.9:1 */

  /* 橙 —— 品牌与动作 */
  --orange:        #ff6b00;   /* 产品主橙，暗底 6.2:1 */
  --orange-soft:   #ff8559;   /* logo 渐变起点，hover / 渐变 */
  --orange-glow:   #ff6b0026;

  /* 金 —— 语义点缀 */
  --gold:          #d4b87a;   /* 暗底 9.2:1 */
  --gold-bright:   #e8d4a2;
  --gold-dim:      #d4b87a80;
}
```

以上比值均为实测（sRGB 相对亮度），非估算。

**用色纪律**

- `--orange` 用于：主 CTA、标题中的重点词、区块序号、功能图标、链接 hover、焦点环。
- **橙底按钮必须用黑字** —— 白字对 `#ff6b00` 仅 2.9:1，不达标；黑字 7.4:1。见 §7。
- `--gold` 用于：分歧/冲突标记、细分隔线、数字与数据。**不与橙争夺强调位** —— 同一屏内橙金并置时，橙管"这里可以点"，金管"这里要留神"。
- 大面积橙底或金底禁止，两者都只作前景、细线与小面积填充。
- 产品截图放进 `--surface` 内嵌框 + `--border` 细描边。**暗色主题截图优先**（`assets/brand/lucimix-c-交叉验证-暗色.png` 已确认产品有暗色主题），与页面几乎无缝。

#### 3.1.1 明暗节奏

七个区块全暗到底会闷。**§4.5 模型矩阵反转为 `--bg-light` 暖米色块**：

- 它是一组模型名与三张模式卡，本就适合安静的浅色处理
- 位置正好在页面中段，把长暗场断开换气
- 反转段内：文字用 `--text-on-light` / `--text-on-light-2`
- **`#ff6b00` 在 `#f2efe9` 上仅 2.5:1** —— 连非文本 UI 的 3:1 都不到，浅色段内一律改用 `--orange-on-light` `#b34700`（4.8:1）。品牌橙仅可作为该段内的**实心填充底**（如按钮底），其上配黑字
- 金 `#d4b87a` 在浅底上 1.7:1，**该段完全不使用金**

其余六个区块全部使用 `--bg` / `--bg-elev` 交替。

### 3.2 字体

| 用途 | 字体 | 备注 |
|---|---|---|
| 中文标题（衬线） | **思源宋体 / Noto Serif SC** | 免费可商用。`QingNiao` 是子集字体，正文不可用（见 01 文档 §1.3） |
| 中文正文 | Noto Sans SC → `PingFang SC, Hiragino Sans GB, Microsoft YaHei` | 继承产品字体栈 |
| 拉丁 | Inter | 产品在用 |
| 数字 | JetBrains Mono，500 | 继承产品 `--ff-number`，用于模型数量、光点、用量 |

**中文衬线必须做子集化**：全字符集思源宋体 5MB+，直接引入会毁掉 LCP。构建期扫描所有标题文案，用 `fonttools` 子集化，目标 < 60KB woff2。这是实现阶段的必办项，不是优化项。

### 3.3 排版阶梯

继承产品 token 并向上延伸（官网需要比产品更大的展示级字号）：

| 名 | 尺寸 | 用途 |
|---|---|---|
| `--fs-display` | `clamp(40px, 6vw, 76px)` | 首屏主标题 |
| `--fs-h1` | `clamp(30px, 4vw, 46px)` | 区块标题 |
| `--fs-h2` | `clamp(22px, 2.4vw, 30px)` | 子标题 |
| `--fs-lead` | `clamp(16px, 1.4vw, 20px)` | 首屏副标题、区块导语 |
| `--fs-body` | `16px` | 正文（= 产品 `--fs-body-md`） |
| `--fs-sm` | `14px` | 辅助 |
| `--fs-cap` | `13px` | 标注（= 产品 `--fs-caption`） |

圆角、阴影直接沿用产品阶梯：`4 / 8 / 12 / 16 / 20 / 24`。

### 3.4 背景与动效

- **粒子层**：复用品牌开场页的 canvas 方案（源码已存 `assets/brand/brand-splash-lucimix.com.html`）。参数沿用：20–90 个星点 + 2–3 个巨型极淡光斑，景深视差（大光斑速度 ×0.6），约 16% 金色粒子，约 45% 小点为实心核。**仅在首屏渲染**，离开视口即 `cancelAnimationFrame`。
- **滚动进场**：区块以 `IntersectionObserver` 触发，`opacity + translateY(16px)`，280ms `ease-out`，一次性。不做视差滚动。
- **`prefers-reduced-motion: reduce`**：粒子不启动，模拟对话直接显示终态全文，进场动画取消。所有内容仍完整可读。

### 3.5 不做的事

- **吉祥物** —— WorkBuddy 有机器猫，我们不做。暗场 + 中文衬线的调性与吉祥物互斥。
- 视差滚动、鼠标跟随光效、滚动劫持。
- 大面积渐变与玻璃拟态。橙金细节 + 暗场留白已经足够，再加会脏。

## 4. 页面结构

七个区块，顺序即说服顺序：定位 → 凭什么 → 怎么融入生活 → 产出去哪了 → 用的是谁的模型 → 平台是什么 → 开始用。

### 导航

固定顶栏，滚动 8px 后加 `backdrop-filter: blur(12px)` 与底部细线。

```
▮ lucimix    交叉验证  定时任务  生态应用  定价        登录  [ 免费使用 ]
```

- 前三项为页内锚点。「定价」在 v1 也做成锚点（指向 §4.7 尾部 CTA 区内的光点说明），**不留死链**。
- 「免费使用」= 主 CTA，`--orange` 实心 + **黑字**；「登录」为文字链。

- 移动端折叠为汉堡菜单，主 CTA 常驻不折叠。

### 4.1 首屏 · 定位 + 模拟对话

**结构**（参考 WorkBuddy 的上下分工）

```
┌─────────────────────────────────────────────────┐
│  [导航]                                          │
│                                                 │
│           你的专属 · 全能 AI 工作台                 │  ← 中文衬线，--fs-display
│                                                 │     「全能」二字用 --orange
│      副标题（见下），--fs-lead，--text-2           │
│                                                 │
│     [ 免费开始使用 ]    [ 看它怎么用 ↓ ]            │
│                                                 │
│   ╭───────────────────────────────────────╮     │  ← 从底部升起，露出上 2/3
│   │ ● ● ●                        模拟对话  │     │     被视口底裁切
│   │                                       │     │
│   ╰───────────────────────────────────────╯     │
└─────────────────────────────────────────────────┘
```

**主标题**：`你的专属 · 全能 AI 工作台`

沿用登录页已上线文案（见 01 文档 §2.1），不另起。「全能」用 `--orange`。

**副标题**（实现按此，不再取舍）：

> 国产与世界前沿模型全部接入。产出自动沉淀，任务定时执行，结果直接送到微信。

三句都是可验证的事实，且三句竞品都做不到（单一厂商无法"全部接入"；豆包/Kimi/元宝无产出库、无推送能力）。

已考虑并否决的备选，记录在此以免重开：

> ~~别的 AI 你不问，它就不存在。Lucimix 会自己找你。~~
> 更锋利，但把「推送」提到首位，与本区块演一轮普通对话（决策 6）的安排错位。该句改用在 §4.3 的导语里。

**CTA**

- 主：`免费开始使用` → 登录/注册页，`--orange` 实心 + **黑字**，圆角 12px
- 次：`看它怎么用 ↓` → 锚点滚动到 §4.2，描边按钮，`--border-strong`

**模拟对话窗口**

- 深色窗口（`--surface`）+ `--border` 细描边 + 顶部三个圆点，宽 `min(1040px, 92vw)`，从视口底部升起并被裁切，暗示"下面还有"。
- 自动播放**一轮普通对话**（决策 6），内容取自素材库 `B1 周报` 场景 —— 全库人群最宽的一条：

  1. 用户气泡打字机逐字出现：`把我这周记的工作内容整理成周报，正式一点，500 字以内`
  2. 顶部出现模式条：`智能模式 · 已为你选择` + 被选中的模型名，金色细标
  3. AI 回复流式逐段出现，结构化（本周完成 / 关键进展 / 遇到的问题 / 下周计划）
  4. 右上角浮出文件卡片：`周报-第34周.md 已存入文件库`，金色描边
  5. 停 2.5s → 淡出重播

- 循环播放；`prefers-reduced-motion` 下直接显示终态。
- 打字速度：用户气泡 45ms/字，AI 回复 12ms/字（明显快于用户输入，暗示"它很快"）。
- **窗口内容为重建，非截图**。理由：静态图演不出流式输出与文件自动归档这两个动作，而这一屏的说服力正来自「它在动」。截图的职责在 §4.2 之后的功能区。

### 4.2 交叉验证 · 凭什么是你

全站最重要的区块。差异化在这里落地。

**标题**：`三个模型背靠背作答，不一致的地方会被标出来`

**导语**：

> 单个 AI 在编的时候，不会告诉你它在编。
> 这不是能力问题——它只有一个视角，没法发现自己错了。

**呈现**：左文右图。

- 左：三条要点
  1. **多模型背靠背** —— 同一个问题独立作答，互不参考
  2. **自动合并去重** —— 一致的沉淀为共识
  3. **分歧单独标出** —— 不合成一个看起来很确定的结论
- 右：**真实截图 #1**（交叉验证结果界面，能看到共识与分歧标记），放入 `--surface` 内嵌框 + 金色细描边。

**落点文案**：

> 出错的地方会被标出来。

**⚠️ 话术约束**：不用「多模型对比」「暴力模式」「更强/最优」；不承诺「保证正确」。见 01 文档 §5.2。

### 4.5 模型矩阵 · 用的是谁的模型

**标题**：`不绑定任何一家`

**呈现**：模型名网格，两行分组，`JetBrains Mono` 排版：

- **国产**：DeepSeek · Kimi · GLM · Qwen …
- **世界前沿**：Claude · GPT …

沿用登录页已上线的表述（01 文档 §2.1）。

**三种模式说明**，横向三卡：

| 模式 | 一句话 | 什么时候用 |
|---|---|---|
| 智能模式 | 系统自动选最合适的模型 | 长、日常、随手问、自己看 |
| 交叉验证 | 多个模型背靠背，分歧标出 | 短、重要、要对外交付、错了要担责 |
| 自定义模型 | 手动指定 | 明确知道某个模型在这件事上更强 |

判断标准直接写出来：**这段内容错了要不要担责？**（素材库原文，是全库最好用的一句话）

**⚠️** 表中「交叉验证」为对外名；产品 UI 内叫「暴力模式」，官网一律不出现。

### 4.6 生态应用 · 一个账号，一份光点

**标题**：`平台上的应用，不用各自注册、各自付费`

**导语**（两条，只讲这两条就够）：

> **一个账号通用。** 平台上的应用不用挨个注册登录。
> **一份光点通用。** 不管用哪个应用，消耗的都是同一份光点——不需要在每个应用里单独充值。

这是与"下载一堆 AI 小工具、每个都要单独付费"最直观的区别。

**三张应用卡**（取自 `应用点-生态应用.md`）：

## 6. 技术方案

**栈**：Vite + React + TypeScript，纯 CSS（CSS 自定义属性），无 UI 框架。

理由：

- 与产品端一致（两端都是 Vite + React），团队维护无切换成本，design token 可直接搬
- 页面高度美术导向，Tailwind 的类堆叠在这种页面上是负担
- P1 的应用点落地页要由 30 条素材数据驱动生成，React 在那一步明显更合适；首页就按同一套骨架起

**目录**

```
src/
  main.tsx
  App.tsx
  styles/
    tokens.css        # §3.1 色板 + §3.3 排版阶梯
    base.css          # reset、字体声明
  components/
    Nav.tsx
    Hero.tsx
    ChatSimulation.tsx    # 首屏模拟对话
    ParticleField.tsx     # 粒子 canvas
    CrossCheck.tsx        # §4.2
    ScheduledTasks.tsx    # §4.3
    FileLibrary.tsx       # §4.4
    ModelMatrix.tsx       # §4.5
    Ecosystem.tsx         # §4.6
    FinalCta.tsx          # §4.7
    Footer.tsx
    ui/                   # Button、SectionHeading、ScreenshotFrame、Reveal
  content/
    copy.ts               # 全站文案集中一处，便于审校与后续 i18n
  hooks/
    useTypewriter.ts
    useInViewOnce.ts
public/
  fonts/                  # 子集化后的思源宋体 woff2
assets/screenshots/
```

**文案集中在 `content/copy.ts`**：全站对外表述受 01 文档 §5 的禁区与话术纪律约束，集中管理才能一次性审校，也为将来英文版留口。

**构建期字体子集化**：`scripts/subset-fonts.mjs`，扫描 `copy.ts` 中出现在标题层级的汉字，用 `fonttools` 产出 woff2。目标 < 60KB。

**部署**：静态产物。

## 7. 响应式与性能

| 断点 | 处理 |
|---|---|
| ≥1280px | 完整布局，左右分栏区块横排 |
| 768–1279px | 左右分栏改上下堆叠，截图满宽 |
| <768px | 单列；导航折叠为汉堡（主 CTA 常驻）；首屏模拟对话窗口宽 `94vw` 并压缩内容行数；粒子数量降到上限 30 |

**性能**

- 首屏 LCP < 2.5s（4G）。LCP 元素是主标题文字，因此中文衬线必须子集化并 `font-display: swap`
- 截图导出 WebP，`<img loading="lazy" decoding="async">` + 显式宽高防抖动
- 粒子 canvas 离开视口即停 rAF；移动端降数量
- 模拟对话用 `IntersectionObserver` 触发，不在页面加载时就跑

**可访问性**

全部实测值（sRGB 相对亮度计算，非估算）：

| 组合 | 比值 | 判定 |
|---|---|---|
| `--text` `#f7f5f2` on `--bg` | 16.1:1 | ✓ |
| `--text-2` `#a3a09a` on `--bg` | 6.7:1 | ✓ 正文可用 |
| `--text-3` `#8a877f` on `--bg` | 4.9:1 | ✓ 正文可用（余量小，勿再调暗） |
| `--orange` `#ff6b00` on `--bg` | 6.2:1 | ✓ |
| `--gold` `#d4b87a` on `--bg` | 9.2:1 | ✓ |
| **黑字 on `--orange`** | **7.4:1** | ✓ 橙底按钮用此组合 |
| ~~白字 on `--orange`~~ | 2.9:1 | ✗ **禁用** |
| `--text-on-light` on `--bg-light` | 15.3:1 | ✓ |
| `--text-on-light-2` on `--bg-light` | 6.6:1 | ✓ |
| ~~`--orange` on `--bg-light`~~ | 2.5:1 | ✗ **禁用**，改用 `--orange-on-light` |
| `--orange-on-light` `#b34700` on `--bg-light` | 4.8:1 | ✓ |
| ~~`--gold` on `--bg-light`~~ | 1.7:1 | ✗ **禁用** |

关键结论：**橙底按钮一律黑字**；**浅色段内的橙一律用 `#b34700`**；**金不出现在浅色段**。
- 所有截图有中文 `alt`
- 键盘可达：跳转链接、焦点环用 `--orange`（暗场）/ `--orange-on-light`（浅色段）、锚点滚动后焦点落到目标区块标题
- 模拟对话对读屏器为 `aria-hidden`，另提供一段等价文字描述
