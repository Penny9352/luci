## 1. 线上资产盘点

### 1.1 三个线上入口

| URL | 实际是什么 | 技术栈 |
|---|---|---|
| `lucimix.com/` | **品牌开场页**（不是产品，也不是官网） | 原生 HTML + Canvas，无框架 |
| `lucimix.com/login` | C 端产品登录页 | React + Vite SPA |
| `biz.lucimix.com/` | B 端产品（企业版） | React + Vite + Ant Design |
| `10.20.4.215:5175` | 旧版 B 端官网（内网） | **本机 shell 不可达**，仅用户浏览器可开 |

> ⚠️ 旧版 B 端官网未能查看。做 B 端站之前需要补：截图，或把该服务暴露到可访问网络。

### 1.2 Logo

文件：`assets/brand/lucimix-logo.svg`（源 `/favicon.svg`，两端共用）

- 292×292 圆角方形（`rx=50`），内含图形
- **形态**：左右两片向中心收束的翼/刃，中间一个方形外框包住一个小方核
- **语义**：多路汇聚 → 一个核心。和「大模型聚合」的产品内核天然同构，这是可以直接拿来当官网叙事母题的资产
- **配色**：前景 `#0052ff`，背景亮色模式 `#ffffff` / 暗色模式 `#1a1a1a`（SVG 内置 `prefers-color-scheme` 切换）
- 无文字标（wordmark）。官网需要的横版组合标待补

### 1.3 品牌开场页拆解（`lucimix.com/`）

这是目前**唯一有独特性**的视觉资产，其余全是标准 SaaS 蓝。副本已存 `assets/brand/brand-splash-lucimix.com.html`。

**内容**：《道德经》第二十一章「道之为物，惟恍惟惚」。动画用 `mask-image` 线性渐变把「恍」「惚」的**竖心旁抹掉**，露出「光」「忽」，落到公司名「**光忽智能**」。

品牌名的来处是道德经 —— 这一层是真实的品牌资产，不是装饰。

**视觉参数**：

| 项 | 值 |
|---|---|
| 底色 | `#000` |
| 主文字 | `#fff` |
| 强调/落定色 | `#d4b87a`（暖金） |
| 次要文字 | `#666` / `#888` |
| 中文衬线 | `QingNiao`（青鸟），内嵌 base64 woff2 |
| 无衬线 | `Noto Sans SC`，Light 300，字距 `.07em`～`.35em` |
| 大字号 | `clamp(43px, 6.6vw, 70px)` |
| 背景 | Canvas 粒子：20–90 个星点 + 2–3 个巨型极淡光斑，含景深视差（大光斑速度 ×0.6）、约 16% 粒子为金色、约 45% 小点为清晰实心核以制造虚实对比 |

> ⚠️ **QingNiao 字体是子集**，只内嵌了「道之为物惟恍惚光忽智能」这十来个字的字形，**无法直接用于官网正文**。若要延续这套衬线气质，需要拿到完整字体授权，或改用可商用的中文衬线（思源宋体 / 霞鹜文楷等）替代。这是黑金方案的第一个待办。

### 1.4 产品端已有的 Design Token

两端共用同一套 token 命名，是同一个设计系统分叉出来的。官网应当**继承这套阶梯**，以免官网点进产品出现断层。

**字号阶**（`--fs-*`）：13 / 14 / 16 / 18 / 24
**字重阶**（`--fw-*`）：400 正文、500 数字、600 标题与强调
**圆角阶**（`--r-*` / `--radius-*`）：4 / 8 / 12 / 16 / 20 / 24
**阴影阶**：`sm` `0 1px 2px` → `md` `0 4px 12px` → `lg` `0 8px 32px`

**字体栈**：

| 用途 | 栈 |
|---|---|
| 界面主字 | `Inter` / `DM Sans` → `-apple-system, BlinkMacSystemFont, Segoe UI, PingFang SC, Hiragino Sans GB, Microsoft YaHei, sans-serif` |
| 数字 | `JetBrains Mono`（`--ff-number`，18px / 500） |

数字用等宽这条值得官网沿用 —— 光点余额、模型数量、用量这类数字在官网上会大量出现。

**语义色**：

| 语义 | 亮色 | 暗色 |
|---|---|---|
| success | `#2e7d5b` | `#0f2a1c`(bg) |
| danger | `#c0392b` | `#f87171` |
| reasoning（思考过程） | `#b8860b` / bg `#fbbf240f` | `#d4a847` / bg `#fbbf2414` |

> 注意 reasoning 用的是**琥珀金** `#d4a847`，和品牌开场页的 `#d4b87a` 几乎同色。产品里其实已经有金色，只是没被当作品牌色使用。这是黑金方案的一个有利伏笔。

### 1.5 品牌色现状：四套并存

用户认为「有 LOGO，没定品牌色」，实际线上跑着四套互不相同的主色：

| 位置 | 主色 | 底色 | 气质 |
|---|---|---|---|
| Logo | `#0052ff` 电蓝 | `#fff` / `#1a1a1a` | 锐利、科技 |
| B 端产品 accent | `#006dd3` 深蓝 | `#0a0a0f` / `#fafafa` | 稳、企业级 |
| C 端产品（另一套主题） | `#101010` / `#f5f5f5` 纯黑白 | `#0f0f0f` / `#fff` | 克制、编辑感 |
| 品牌开场页 | `#d4b87a` 金 | `#000` | 东方、道德经 |

`#0052ff` 与 `#006dd3` 是两个肉眼可辨的不同蓝，同时出现在 logo 和产品 UI 上 —— 这是需要在官网立项时一并收口的品牌债。

**已定方案（决策 4）**：官网以**黑金**为基调（`#000` 系底 + `#d4b87a` 金），`#0052ff` 收窄到主 CTA 与交互态。

## 2. C 端内容盘点

来源：`Lucimix产品介绍/product-brief-c.md`（v0.2, 2026-08-12）、`Lucimix产品运营/应用点素材库.md`（v1.0, 30 条）及六份应用点文档。

### 2.1 定位

产品自述：**面向个人用户的 AI 工作台** —— 聊天、文件管理、定时任务、手机端使用；同时作为平台承载开发者上架的外部应用，提供统一用户体系与计费结算。

C 端产品线上 `<title>` 已经是：**「Lucimix — 你的全能 AI 工作台」**。与决策 3 的首屏方向一致。

设计原则：**入口很宽，天花板不低**。小白开箱即用，深度用户有模型选择、文件库、定时任务、API 等进阶能力。

### 2.2 功能四层

| 层 | 内容 |
|---|---|
| 一 · 模型调度 | 智能模式（自动选单模型）/ 暴力模式（多模型聚合，**对外称"交叉验证"**）/ 自定义模型 |
| 二 · 产出可管理 | 文件库（全部 / 我的云盘 / 对话内文件 / 图片生成 四 tab）、工作区侧栏、从资料库引用到对话、图片生成、对话历史管理 |
| 三 · 融入日常 | 微信/飞书/企微扫码绑定、定时任务（标题≤25字、描述≤500字、频率+时刻、推送渠道、每任务独立指定模型）、API Key（OpenAI 兼容）、光点充值、邀请双向各 1000 光点、用量统计 |
| 四 · 平台生态 | 外部应用上架、统一用户体系（一个账号）、集中计费结算（一份光点） |

### 2.3 差异化排序（我的判断）

按「竞品能否做到」排：

1. **交叉验证** —— 最锋利。多模型背靠背独立作答，系统自动合并去重，一致的沉淀为共识，不一致的标为冲突。豆包/Kimi/元宝**结构上做不到**，因为它们只有一个模型。卖点原句：*"单个 AI 编的时候不会告诉你它在编，三个 AI 背靠背，不一致的地方自己就露出来了。"*
2. **定时任务 + IM 推送** —— 最具体可感。"每周五下午周报自己写好发到我微信"。竞品有类似能力，差异化中等，但转化说服力强。
3. **一个账号 + 一份光点通用** —— 平台叙事。用户不为"生态"付费，只为"这个应用刚好解决了我的问题"付费，所以必须落到具体应用点上讲。
4. **一张照片出口播视频**（生态应用）—— 传播力最强，产出物本身就是广告。适合投放落地页，不适合首屏。

### 2.4 用户光谱

| 类型 | 用什么 |
|---|---|
| 纯小白 | 智能模式、一句话对话 |
| 日常效率型 | 智能模式 + 定时任务 + 文件库 |
| 深度用户 | 自定义模型 + 交叉验证 + 文件库全功能 |
| 技术/开发者 | API Key + 自定义模型 + 用量统计 |
| 外部应用商家 | 应用接入 + 用户体系打通 + 集中计费 |

首页场景示例覆盖育儿英语启蒙、商务邮件、家常菜、区块链科普、家电选购、PDF 整理 —— **工作与生活并重**，不是纯职场效率工具。官网选图选文案要守住这一点。

### 2.5 素材库结构（30 条应用点）

每条含四字段：**场景+提示词 / 产品能力 / 人群标签 / 预期产出**。这四个字段就是应用点落地页的现成信息架构。

分组：交叉验证 10 / 定时任务+IM 6 / 智能模式 3 / 内容创作·副业 5 / 研发·独立开发者 3 / 生态应用 3。

标星的高价值条目：
- `A9` 引用与数据交叉核查 ★
- `B2` 每天早上一份行业情报，哪条不靠谱会标出来 ★★
- `C3` 模式选择指南（组合打法）★
- `D1` 服装批量换装出图 ★★
- 生态 `F1` 小红书口播账号自动运营 ★★（"一张照片 + 一条参考视频 → 口播视频 + 配套文案"）

## 3. B 端内容盘点（留待第二阶段）

来源：`Lucimix-Enterprise-销售介绍.pdf`（12 页）。叙事结构已经成型，几乎可直接映射成页面：

1. **痛点**：六件失控的事 —— 看不见全貌 / 敏感数据风险 / 模型选择困难 / 成本算不清 / 员工难上手 / 密钥管理混乱
2. **解法主句**：**「三大入口用 AI，一个底座管 AI」**
3. **三大入口**：智能对话（面向全员，IM+Web）/ 高阶 Agent（面向高级用户，独享云端虚拟机、持久记忆、长时任务）/ 统一 API（面向开发者，一个 Key 接入一切、协议兼容）
4. **治理底座**：看得清成本（统一计费、预算熔断、分部门看板）/ 内容管控四步闭环（风控规则 → 自研识别模型 → 敏感数据私有化路由 → 完整审计）/ 守得住数据（智能日志总结、异常行为识别、API 私用预警、全链路追溯）
5. **三方对比表**：部门各用各的 vs 只用一个大厂 vs Lucimix（模型选择 / 成本 / 安全合规 / 运维 四维）
6. **能力基石**：多样 · 强大 · 稳定
7. **四类场景**：日常办公提效 / 研发提速 / 敏感业务隔离 / 管理层决策
8. **收束句**：管理可见 · 监管可控 · 门槛降低

主体：北京光忽智能科技有限公司。

## 4. 竞争格局

来源：`WorkBuddy竞品全景清单（含第三方AI聚合平台）.html`（2026-08 整理，26 家）。参考对象：`workbuddy.ai`、`kimi.com`。

| 层 | 竞争性质 | 代表 |
|---|---|---|
| 同类办公 Agent / AI 工作台（8 家） | **直接竞争** | Trae Work、扣子 Coze、千问办公、豆包、AiPy、腾讯元宝、Genspark、ChatGPT GPTs |
| 开发者 API 聚合平台（10 家） | 供给层间接竞争（企业可自建网关绕开一站式方案） | 微元算力、硅基流动、千帆、百炼、火山方舟、OpenRouter、星宇智算、ModelPort、非线智能、快快云 |
| 用户端 AI 聚合工具（8 家） | 注意力间接竞争 | Poe、ChatHub、TypingMind、纳米AI、ChatALL、Perspective AI、元象 XAgent、智媒 |

**对官网的含义**：C 端所处市场里豆包、Kimi、元宝、纳米 AI 全部免费。「免费开始使用」这句话在中国市场已无说服力 —— 用户不缺一个免费 AI 对话框，他已经有三个了。官网必须回答的是「凭什么是你」，而不是「怎么开始」。

## 5. 硬约束

### 5.1 严禁写入任何对外物料的场景

来自素材库附录，**超出产品当前能力，写了会造成预期落差或合规问题**：

| 场景 | 原因 |
|---|---|
| Excel 多表合并 / 数据清洗 / 透视表 / 自动图表 | 需本地文件读写 |
| **PPT 自动生成并保存到本地** | 同上。注意这是国内 AI 工具最大的单一心智（竞品该场景内容普遍 6000+ 赞），但确实做不了 |
| PDF / 扫描件 / 合同批量处理与格式转换 | 需本地文件操作 |
| 会议录音转写与说话人区分 | 需音频处理 |
| 本地文件批量重命名 / 整理 / 远程控制客户端 | 需桌面客户端 |
| 建站 / 部署 | 超出能力 |
| Skill 市场 / 插件生态 | 产品暂无此机制 |
| 漫剧 / 绘本 / 多角色连续分镜 | 图片生成不支持复杂分镜与连续叙事 |
| 降 AIGC 检测率 / 降重 / 代写论文 | 能力无效 + 合规违规，双重禁止 |
| 「搭建工作台」 | 无配置保存与一键复用机制 |

### 5.2 话术纪律

| ✅ 用 | ❌ 不用 | 原因 |
|---|---|---|
| 交叉验证、分歧标红、多模型背靠背 | **多模型对比** | 该词在小红书已被天梯图/评测内容占据 |
| 智能模式 / 自定义模型 | **暴力模式** | 内部叫法，不对外 |
| 具体动作与产出 | 更强 / 最优 | 空洞 |
| **"出错的地方会被标出来"** | "保证正确" | 不可承诺 |

**模式选择的唯一判断标准**：这段内容错了要不要担责？要担责 → 交叉验证；日常随手问 → 智能模式；明确知道某模型更强 → 自定义模型。

### 5.3 决策 3 的风险与缓解

「一站式 AI 工作台」这句定位与豆包、Kimi、Trae Work 的官网首屏几乎同构，单靠这一句区分不开。结构上补两处：

1. 首屏副标题必须带一个**只有 Lucimix 成立的事实性限定**（不是形容词）
2. 第二屏立刻用**交叉验证**回答「凭什么是你」

首屏保持定位完整性，锋利度由第二屏承担。

## 6. 对官网设计的推导结论

### 6.1 三种目标 → 三种流量 → 三类页面

| 目标 | 人从哪来 | 落在哪页 | 心里的问题 |
|---|---|---|---|
| 拉注册 | 搜索、口碑、已有意图 | 首页 | "怎么开始" |
| 说清这是什么 | 听人提过、在比较豆包/Kimi | 首页第二屏之后 | "凭什么用你" |
| 承接投放 | 小红书/抖音某条内容 | 应用点落地页（**不经过首页**） | "内容里那个东西怎么弄" |

投放流量不经过首页，所以目标 3 与首屏不冲突 —— 它是另一套页面。

### 6.2 优先级

- **P0 · 首页** —— 一站式工作台定位打头 + 交叉验证承接说服 + 注册 CTA 贯穿全站。同时承担目标 1 和 2。
- **P1 · 应用点落地页模板** —— 一套模板套 N 条应用点。ROI 最高：素材库 30 条已写好场景/提示词/人群/产出，正是落地页字段结构。
- **P2 · 解释性页面** —— 光点与定价、开发者（API）、生态应用、IM 绑定引导。

第一期建议：P0 + P1 模板（含 2–3 个样例应用点），P2 先留导航位。

### 6.3 可直接复用的设计资产

| 资产 | 怎么用 |
|---|---|
| Logo 的「两翼向中心收束 + 方核」形态 | 官网叙事母题：多路模型汇聚成一个答案 |
| 品牌开场页的黑金 + 粒子 + 景深 | 官网基调（决策 4） |
| 产品 token 的字号/圆角/阴影阶 | 官网直接继承，避免官网→产品的视觉断层 |
| `JetBrains Mono` 数字字体 | 光点余额、模型数量、用量等数字 |
| 产品里已存在的琥珀金 `#d4a847` | 佐证金色并非外来色 |
